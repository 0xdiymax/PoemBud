# PoemBud 单机版开发任务

## 1. 里程碑规划

### M1：离线诗库接入

目标：App 从本地 rawfile 读取真实诗词数据，替换页面内硬编码的少量诗词。

任务：

| ID | 任务 | 产出 | 优先级 |
| --- | --- | --- | --- |
| M1-01 | 定义 `PoemItem`、`PoemCategory` 类型 | 新增模型文件 | P0 |
| M1-02 | 读取 `offline_poem_library.json` | 本地诗库加载器 | P0 |
| M1-03 | 将首页推荐、热门诗、学习页诗文改为读取本地诗库 | 页面数据源替换 | P0 |
| M1-04 | 处理无封面、无音频的诗词状态 | 默认图/禁用音频按钮 | P0 |
| M1-05 | 保留现有 4 首诗的图片和音频映射 | 资源映射表 | P1 |

验收：

- 删除网络后仍可展示 39 首本地诗词。
- 点击任意诗词进入学习页，标题、作者、正文、拼音正确。
- 没有本地音频的诗不播放错误音频。

## 3. 建议实现顺序

1. 先接入本地诗库加载器，解决“真实数据源”。
2. 再做诗库搜索和分类，让数据能被用户找到。
3. 然后改学诗页动态渲染，覆盖不同长度诗文。
4. 同步移除跟读页 AI 文案，改成本地录音练习。
5. 最后做题库、成长报告和设置页。

## 4. 技术约束

- 运行时不访问 GitHub、今日诗词、aspoem、we-drawing 或任何诗词 API。
- 数据更新只能通过发版内置新 JSON/资源。
- 不复制 `aspoem` 代码，避免 AGPL 传染风险。
- 如果后续大量使用 `chinese-poetry` 数据，需要在 App 的“关于/开源许可”中保留 MIT license notice。
- 当前 `offline_poem_library.json` 在 rawfile 中，后续如体积增大，应考虑拆分为多个 rawfile 或构建期生成索引。
