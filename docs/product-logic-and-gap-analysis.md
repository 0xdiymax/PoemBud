# PoemBud 产品逻辑与功能缺口梳理

> 说明：本文档保留最初对 `output` 目标图和实施前代码的差距梳理，用作需求来源追踪。当前 MVP 已按“单机、无 AI、无运行时诗词网络接口”的方向收敛，执行口径以 `docs/offline-app-prd.md`、`docs/offline-app-development-tasks.md` 和 `docs/mvp-implementation-notes.md` 为准。

## 1. 梳理依据

本次梳理基于两类资料：

- 目标图：`output/imagegen/ancient-poetry-kids-app/` 下的 7 张页面图，包括首页、诗单、学诗、跟读、闯关、成长报告、个人中心。
- 实施前实现：`entry/src/main/ets/pages/Index.ets`、`entry/src/main/ets/model/PoemBudStore.ets`、音频与录音工具类、路由配置和资源文件。

实施前工程已经具备一个单机版学习闭环雏形：诗词展示、范读播放、收藏、录音、模拟评分、补字闯关、成长数据和本地档案。后续 MVP 没有采用目标图中的评测服务方向，而是按单机版 PRD 替换为本地录音练习、动态闯关和本地成长记录。

## 2. 当前产品主逻辑

### 2.1 信息架构

当前底部 Tab 为：

| Tab | 当前页面 | 主要职责 |
| --- | --- | --- |
| 首页 | `HomePage` | 今日推荐、轮播、热门古诗、学习进度、跟读/阅读入口 |
| 诗库 | `CollectionPage` | 我的收藏、诗单分类、最近学习 |
| 学习 | `StudyPage` | 当前诗文学习页，展示诗文、拼音、范读、逐句讲解 |
| 我的 | `ProfilePage` | 本地档案、统计、勋章、诗单、服务入口 |

二级路由为：

| 路由名 | 当前页面 | 入口 |
| --- | --- | --- |
| `poem` | `StudyPage` | 首页轮播、热门诗、诗库、最近学习、闯关查看诗文 |
| `reading` | `ReadingPracticePage` | 首页跟读、学习页跟读 |
| `challenge` | `ChallengePage` | 学习页背一背 |
| `growth` | `GrowthPage` | 首页学习进度、我的学习报告/成就墙 |
| `info` | `InfoPage` | 分类、更多、设置、家长中心、帮助等占位说明 |

### 2.2 内容与资源

当前内置诗词内容 4 首：

- 《静夜思》
- 《登鹳雀楼》
- 《望庐山瀑布》
- 《咏鹅》

每首诗当前包含：

- 标题、作者、朝代
- 4 句诗文
- 每句拼音字符串
- 逐句解释
- 缩略图、横幅图、音频 rawfile
- 简单补字闯关题

目标图中额外出现但当前未形成完整内容对象的诗包括：

- 《春晓》
- 《小池》
- 《清明》
- 《山行》
- 《枫桥夜泊》
- 诗单分类中的“唐诗 / 咏月诗 / 春天的诗 / 山水田园”等更多诗集

### 2.3 数据模型

当前核心数据结构为 `PoemBudData`，持久化在 Preferences：

| 数据域 | 当前字段 | 当前用途 |
| --- | --- | --- |
| `profile` | 登录状态、昵称、ID、称号、等级、经验百分比 | 本地档案展示 |
| `progress` | 今日分钟、连续天数、累计天数、已学数、掌握数、星星、本周指标 | 首页进度、成长页、我的统计 |
| `reading` | 尝试次数、最好分、最近分、最近录音路径、时间 | 跟读结果和跟读记录 |
| `challenge` | 当前关、已过关、闯关星、最近完成时间 | 闯关进度和奖励 |
| `study` | 当前诗、已学诗、已过闯关诗、已听诗 | 推荐诗、最近学习、统计 |
| `collection` | 收藏诗 ID、最近诗 ID | 诗库、我的诗单 |
| `achievements` | 字符串数组 | 最近成就展示 |

当前模型适合单机 demo，但不够支撑目标图里的完整产品：缺少“每首诗的学习进度、每次跟读记录、每日学习记录、分类标签、勋章规则、关卡题库、家长视图、设置项”等结构化数据。

## 4. 跨模块核心缺口

### 4.1 内容库

当前内容库写死在 `Index.ets`，只有 4 首诗。目标产品至少需要一个结构化诗词库：

- 诗词基础信息：ID、标题、作者、朝代、年级/年龄段、主题标签、难度、推荐语。
- 诗文内容：逐字、逐句、拼音带音调、注释、译文、赏析。
- 多媒体资源：封面、横幅、逐句讲解图、范读音频。
- 练习资源：跟读句子、补字题、选择题、排序题、背诵题、写字字帖。
- 分类关系：唐诗、咏月、春天、山水田园等。

建议把诗词数据从页面文件中拆出为独立 `model` 或 `data` 文件，后续再考虑远端内容更新。

### 4.2 学习进度

当前只记录聚合值和部分 ID 数组，无法还原真实学习路径。建议补充：

- `poemProgressById`：每首诗的听赏次数、已读讲解、背诵状态、掌握度。
- `dailyRecords`：按日期保存学习分钟、学习诗、跟读次数、星星。
- `readingAttempts`：每次录音的诗 ID、句子 ID、分数、逐字结果、音频路径、时间。
- `challengeAttempts`：关卡 ID、题目 ID、答案、是否通过、奖励。
- `badgeStates`：勋章 ID、解锁状态、解锁时间、进度。

### 4.3 AI 跟读评测

目标图把跟读评测作为核心卖点，当前只是本地录音加固定分数。需要明确技术路径：

- 本地只录音，上传到服务端评分。
- 或集成端侧语音识别/发音评测 SDK。
- 输出结构至少包含：总分、完整度、准确度、流利度、逐字评分、建议、星级奖励。

没有真实评测前，产品上应标记为“模拟评分”或隐藏 AI 文案，避免功能认知偏差。

### 4.4 闯关体系

目标图是游戏化关卡系统，当前只是单题补字。建议补齐：

- 关卡表：关卡 ID、诗 ID、题型、题目、答案、可选项、难度、奖励。
- 关卡进度：当前关、已完成关、失败次数、是否领取奖励。
- 奖励表：星星、宝箱、诗句卡片、勋章。
- 题型扩展：补字、诗句排序、作者匹配、诗意选择、听音辨句、背诵检测。

### 4.5 成就和勋章

当前勋章基本是静态展示。目标图需要规则驱动：

- 初学乍练：完成首次学习。
- 勤学好问：连续学习 N 天。
- 诗词小达人：掌握 N 首诗。
- 坚持不懈：连续跟读 N 天。
- 出口成章：跟读评分达到某阈值。

建议用“规则 + 状态”的方式计算，而不是手写字符串数组。

### 4.6 信息架构待确认

目标图存在一个不一致点：

- 首页、诗单、个人中心目标图的底部 Tab 是：首页 / 诗库 / 学习 / 我的。
- 成长报告目标图的底部 Tab 是：首页 / 学习 / 成长 / 我的。

当前实现选择了“诗库”为一级 Tab，“成长”为二级页面。需要产品确认：

1. 成长是否升级为一级 Tab？
2. 如果成长是一级 Tab，诗库放到首页入口还是学习入口？
3. 如果诗库保留一级 Tab，成长报告是否只从首页进度卡和我的页进入？

## 5. 建议补齐顺序

### P0：闭环真实可用

1. 扩展诗词内容库，至少补齐目标图出现的诗和分类。
2. 建立每首诗学习进度模型，替代仅用聚合值和 ID 数组。
3. 诗库搜索、分类列表、收藏完整列表。
4. 跟读评测从固定 92 分改成真实评分接口或明确的模拟评分层。
5. 跟读记录改为多条历史，支持按诗/按句查看。
6. 闯关题库、关卡上限和不同关卡题目。
7. 确认底部信息架构：成长是否作为一级 Tab。

### P1：产品体验完整

1. 学诗页补齐“写一写 / 赏析 / 拼音开关 / 逐字拼音”。
2. 热门、收藏、最近学习卡片补齐快捷播放。
3. 周报日期和成长曲线改为真实历史数据。
4. 勋章墙、成就规则和奖励解锁。
5. 家长中心、设置、收藏管理从占位页变成真实页面。
6. 录音权限和失败态提示。

1. 分享学习报告。

## 7. 结论

当前版本已经完成了“儿童古诗学习 App”的基础骨架，能跑通：

`首页发现 -> 学诗 -> 听范读/收藏 -> 跟读录音 -> 闯关 -> 成长报告 -> 我的档案`

但与目标图相比，它更接近高保真原型或单机 demo。要达到目标产品，需要优先把“内容库、诗库检索分类、真实跟读评测、关卡题库、细粒度学习进度”补齐；否则成长报告、勋章、家长中心等模块很难基于真实数据成立。
